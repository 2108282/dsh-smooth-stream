## 极致丝滑的阅读手感

无论是阅读数百行的长篇推演，还是紧盯高速吐字的代码生成，`dsh-smooth-stream` 带来的是一种**沉浸、连贯且零视觉负担**的阅读质感：

- **如水流般自然铺展**：告别大段文本突然“砸”在屏幕上的视觉压迫，字句如打字机般富有呼吸感地逐字涌现；
- **视线无需追赶跳动**：视口如同搭载了高精度阻尼滑轨，随文字增长平稳匀速推移，彻底终结换行时的突发踢移；
- **呼吸感与实时性的平衡**：慢速输出时从容优雅，高并发爆发时平稳追赶，无论模型吐字多快，画面始终从容自若。

## 为什么需要它？

大模型输出是通过网络分块到达的。一个数据包可能在几毫秒内送达数百字符，下一个分块却需要数十毫秒。

如果直接将 DOM 渲染和视口滚动绑定在离散的到达事件上，通常会引发两个阅读体验问题：
1. **视觉跳跃与撕裂**：段落、代码块和表格整段突发呈现，视线被迫频繁重新寻焦；
2. **滚动抖动与重排风暴**：依靠 `scrollTop = scrollHeight` 进行瞬时硬跳；即使用 CSS `scroll-behavior: smooth`，高频写入也会不断重置缓动曲线，导致动画永远无法收敛，高速流下伴随剧烈的主线程重排。

`dsh-smooth-stream` 将**内容呈现**与**视口运动**拆分为两个独立的物理状态机，在每一帧动画回调（rAF）中连续积分，彻底消除跳跃感。

## 核心机理与架构

```
[ 模型 SSE 分块流 ]
         │
         ▼
 ┌─────────────────┐       背压阻尼 (0.55x ~ 1.0x)       ┌─────────────────┐
 │   揭示节奏引擎   │ ◄──────────────────────────────── │   弹簧跟随引擎   │
 │ (Reveal Engine) │                                   │ (Follow Engine) │
 └────────┬────────┘                                   └────────┬────────┘
          │ 字符积压与分数积分                                      │ 二阶阻尼弹簧积分 (k=130, c=24)
          ▼                                                     ▼
 [ 逐帧平滑展开 DOM ] ───────────────────────────────► [ 合成层 Transform 补偿 ]
  (单帧视觉位移 ≤ 8px)                                   (0 Reflow / 纯 GPU 合成)
```

### 1. 动态自适应的揭示引擎（Reveal Engine）
- **分数级字符积分**：根据积压队列深度自适应调节速度（$v = 90 + \text{backlog}^{1.25} \times P$），低负载时从容自然，高积压时平稳追赶，绝不倾泻整段文本。
- **折行限幅平滑**：长文本和代码块发生换行时，单帧视觉位移被限制在 8px 以内，将原本 24~28px 的单帧跳跃平摊至数帧完成。
- **尾部平稳收束**：回合结束标记到达后，残余缓冲区以恒定速率释放，正文、思考链与工具调用之间自然衔接。

### 2. 纯合成层驱动的跟随引擎（Follow Engine）
- **二阶阻尼物理系统**：采用 $k=130, c=24, m=1$ 的亚步进物理弹簧，将内容高度的变化转化为平滑连续的速度与位移轨迹。
- **零重排（Zero-Reflow）位移补偿**：真实滚动容器始终锚定在底部，剩余的视觉滞后完全由外层 DOM 的 `transform: translate3d` 吸收。跟随过程不读写任何触发 Layout 的属性，杜绝重排风暴。
- **闭环背压控制（Closed-Loop Backpressure）**：当跟随滞后接近预留空间时，反向向揭示引擎施加阻尼（最低降至 0.55 倍速），防止文本增长超出视口弹簧范围。
- **掉帧自愈与跨刷新率一致**：主线程卡顿（Stall）时自动钳位物理时间（$\le 32\text{ms}$），避免画面恢复后的突进瞬移；在 60Hz 与 120Hz（ProMotion）屏幕下拥有近乎一致的物理收敛时间。

### 3. 会话生命周期自动折叠（Turn Auto-Collapse）
- 对话进行时，思考链与工具调用保持实时展开；
- 回合结算完成并稳定后，自动将执行过程收敛为一行极简的 `已处理 X 秒` 摘要，保持工作区专注；支持随时点击无缝展开。

### 4. 会话级协议顺序播放（0.11.0-rebuild.4 候选）

本候选版在注入的 Flow 层为会话共用播放队列，依据对话协议顺序而非 DOM 分组顺序安排可见内容。实现细节与验证边界见 [候选版说明](docs/changes-0.11.0-rebuild.4.md)。

- 正文、展开的思考和工具卡按协议序号接续；工具卡保留官方组件及其交互，并作为整体入场。
- 前序流块只有在收到显式结束标记或持久化结算边界后才释放后继；字符耗尽或网络暂时静默不会代替协议结束。
- 进入会话时按 Session 来源快照认领已有正文前缀、思考和工具并直接显示；晚到历史、向前翻页及重新进入会话也不重播，实时新增内容继续按协议顺序播放。
- 设置加载期间保持会话接管，已有内容保留基线；设置就绪后仅为实时新增内容决定播放资格。备用 Native 渲染器每次挂载都保守认领当前全文，随后新增内容仍可播放。
- 插件不再因页面后台事件主动暂停，也不再提供后台恢复方式或恢复协调。WebView 仍可能节流或冻结；不承诺后台持续执行或回到前台必定跳到最新位置。
- 候选版保留 main 原有渲染回退；本说明及旧版性能、动效文字不代表候选版已完成实机观感验证。

### 5. 对话状态栏与底座分割线防抖隔离（Running Status & Baseline Stabilization）
- **精准适配 DSH 原生运行状态容器**：通过 `[data-chat-running]` 与选择器层级回溯，精准识别 Harness 官方底部状态栏（含「深度求索中…」指示器与底部分割线 `runningDivider`），将其从常规消息变换表面（`shiftSurfaces`）中完全隔离。
- **换行轨迹平滑同步推进**：在换行高度激增（`floorNow > trajectoryFloorPx`）瞬间，同步推进物理轨迹位置 `trajectoryPositionPx`，保持视觉位移 `shiftPx` 的绝对连续，彻底终结了“吐字折行时整行被强行向上拉高”的风琴式抽搐。
- **剔除工具/命令步骤交替时的虚假高度叠加**：移除将状态栏瞬态高度 `lastStatusHeightPx` 粗暴累加进预留跑道 `reservePx` 的逻辑，彻底解决“一出现调用工具或使用命令底部就被剧烈拉高、随后缓慢回落”的瞬态突起。
- **跑道物理偏移量严格钳位**：限制 `ensureRunway` 的 offset 不得超过实际跑道尺寸上限，防止文本并发折行高度泄漏污染跑道，使底座分割线和状态栏在全生命周期始终如磐石般稳定锚定在视口底部。

## 内核兼容性

| DSH 内核 | 本插件支持情况 |
|---|---|
| `0.2.2-rc.2` | ✅ 已迁移并验证新版 `ui-conversation` / `ui-chat` slot 与 renderer 契约 |
| `0.1.x` | ❌ 此版本线现已结束支持；请使用 `0.1.x` 兼容发行版 |

- ✅ = 兼容。当前适配基于 `0.2.2-rc.2` 的 `@deepseek-ai/dsh-client-ui-renderer`、`ui-conversation` 和 `ui-chat`。
- `0.2.2-rc.2` 起助手文本通过包装官方 keyed renderer 平滑呈现；官方 renderer 仍拥有 locale、turn-process hooks、图片/思考子 slots、上下文菜单及其余交互。
- Fast pipeline 是独立的可选优化，仅拦截 `animation-frame` publication；关闭插件或设置时保留官方三帧行为。
- **不要对 `@deepseek-ai/*` 包的运行时符号做静态导入**。宿主 CLI 经 `node --import tsx/esm` 启动，tsx 会应用宿主 `tsconfig` 的 `paths` 映射，外部插件对 `@deepseek-ai/*` 的裸导入可能被重定向进宿主源码，一旦宿主侧改名/删符号就会以模块实例化错误的形式炸掉启动。类型导入（`import type`）不受影响。

## 用户偏好设置

在 Web 界面打开 **设置 → 平滑流式**，或通过 **设置 → 插件 → 平滑流式** 打开同一配置卡：

- **启用丝滑流式渲染**（默认开启）：接管回复和工具行的渲染与跟随；关闭后即时恢复 Harness 内置渲染。
- **自动展开思考**：使用官方 disclosure Hook，在推理流式生成时展开，排空或关闭自动展开后收起；保留用户手动选择及官方 Turn reset。已有思考按进入基线直接显示；页面后台事件不再触发插件自动收起或暂停再次展开，手动展开仍遵循官方交互。
- **工具引导语保持流式**：开启后，工具前的正文按会话协议顺序播放，排空并确认结束后再呈现工具；关闭后跳过该部分文字动画，仍保留协议结束边界。工具卡整体入场，内部保留官方渲染。
- **接管滚动**：在新版分组结构上平滑跟随，读者向上滚动后让出控制。长帧只按普通 32ms 动画时间上限推进；页面后台事件不再触发回收或重建跟随，也不触发回前台跳到最新。已交还给 Harness 的滚动容器，重新挂载跟随组件也不再写入预留或位移。发送消息触发宿主折叠动画时，插件根据 `data-input-fold` 让出滚动时钟，回收自身补偿，保留宿主为防折叠回弹而设置的底部占位。关闭时清除插件增加的预留和跟随样式，将滚动交回 Harness。
- **预测预留空间**（调试参数）：仅控制插件额外增加的空间，只有开启“接管滚动”且启用已保存的物理参数时，自定义值才生效。数值是插件预留 margin 与 padding 的合计上限，设为 `0` 禁用额外 runway；调低会回收已有插件预留，同时补偿阅读位置以减少跳动。官方折叠占位、输入框避让和安全区间距不受此参数控制，因此 `0` 不等于聊天底部所有留白都消失。
- **对数淡入**（默认开启）：回答正文和展开的思考内容中，尾部范围随输出速度从 24 扩展到最多 160 个字素，从 0% 不透明度在 240ms 内按反向对数曲线变实（前段更通透，后段变实）。网络停顿时也会恢复清晰；关闭此项保留逐字输出与滚动。遵循动效偏好，跳过代码、公式和思考摘要，不支持文字范围着色的浏览器自动使用原有输出效果。
- **完成后自动折叠**（默认开启）：回合处理完成后，将思考过程与工具调用折叠为摘要行。
- **启用已保存的物理参数**（默认关闭）：独立控制是否使用调试页保存的字符速率、每帧字数和弹簧参数。开启后关闭 HUD 仍然生效；关闭时恢复内置默认值，但保留保存的参数。旧配置迁移时保留原先实际生效状态。
- **显示渲染调试面板**（默认关闭）：在界面右侧开启实时 HUD，观测字符积压与跟随状态并编辑物理参数。此开关只控制诊断显示与采集，不再决定保存的物理参数是否生效。

本候选版由注入的会话 Flow 统一调度受支持的聊天节点，按协议序号播放正文、展开的思考和整体工具卡，共用字符预算；不按工具树 DOM 顺序逐段重播。后继同时等待前序可见文字排空及明确的协议结束边界，工具入场与文字渐隐在启用且可用时也参与完成确认。后端任务仍可并行执行。进入时以 Session 来源快照中的已有正文前缀、思考和工具建立基线，初始历史、晚到历史、向前翻页及会话重入都直接显示；实时新增内容按队列播放。收起的思考同步已有内容，手动展开显示现有快照，只对随后新到达的可见文字播放动画。设置加载期间保留接管与基线。备用 Native 渲染器每次挂载保守认领当前全文，不把挂载时已有正文再次逐字播放。过程组标题保留宿主组件与可见性 Hook；底部运行状态和输入区独立 Todo 面板不纳入聊天节点播放队列。

后台暂停、恢复模式和恢复协调已移除。插件继续使用普通逐帧预算和长帧限幅；实际后台调度由浏览器或 WebView 决定，回到前台不触发插件专用恢复批次或强制跳到最新。

本地淡入预览：执行 `pnpm build:repro`，在仓库根目录启动 `python3 -m http.server 8765 --bind 127.0.0.1`，打开 `http://127.0.0.1:8765/repro/index.html?demo=fade`。预览包含暂停、停止、深浅主题、高速分片和代码/公式保护样例，复用真实输出引擎，富文本为测试样例。

执行 `node scripts/verify-logarithmic-fade.mjs` 可验证并录制预览（需要 Chrome 和 `pnpm exec playwright-core install ffmpeg`；其他 Chrome 路径可用 `CHROME_BIN` 指定），报告与视频保存在未跟踪的 `repro/artifacts/logarithmic-fade/`。
