## 本次要求与范围

用户要求“先修省略号”。仅处理单行工具标题/摘要中，被 CSS 省略号裁掉的文字尾巴仍占用吐字预算、拖住后继工具的问题。

保留可见标题的逐字动画、官方组件结构与事件、原始路径、16 字追赶预算及用户字速/滚动设置。不修改 context 包装规则，不加入恢复耗时/FPS 诊断，不重构滚动控制器，不重启 DSH。

## 修复方式

1. 等当前受控前缀实际显示到省略边界，才考虑同步后面的不可见尾巴；不在入场时直接跳过整行动画。
2. 仅在本插件所拥有的根节点内判断单行 `nowrap + ellipsis + overflow-x:hidden/clip`，用该 Text 自己的 Range 验证，不能只看父容器整体溢出。
3. Range 必须有可靠、非零、有限的同一行几何，且前缀与裁剪区域相交并越过右边界。RTL/双向控制、换行、垂直/居中/独立布局、不可见入场、横向滚动或测量不可用等情况保留原行为，不猜测。
4. 只处理队列前沿，先批量读取，再同步完整源、shown、pending、backlog；不为每个隐藏字继续消费可见预算，也不新增整棵 DOM 扫描。
5. 不删除或截短真实路径；最终 DOM 文本仍为完整源字符串，原文件点击/context-menu 闭包不变。
6. 帧写入前处理尚未交付的 MutationObserver 记录，每批对同一 Text 只处理最终值一次，避免新源被旧前缀覆盖或被多条内部写入误截断。开始观察前清理未被观察的初始写入标记，覆盖首帧前清空的边界。

宽度扩大或解除省略后，已经同步的旧内容保持完整；新追加、现在可见的文字仍走原来的动画。业务工具可以继续处于 running，修复的是呈现接力，不伪造业务完成状态。
