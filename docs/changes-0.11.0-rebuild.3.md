# 0.11.0-rebuild.3：源块播放进度与重新挂载时的渐显修复

本候选在 `0.11.0-rebuild.2` 发布提交 `2d737fc` 上继续修订；main 基线仍为 `d0c96a4651e175d393799168c11b42a9a743649a`（0.10.9），不是上游正式 0.11.0。原候选说明保留在 [rebuild.2 说明](changes-0.11.0-rebuild.2.md)。

## 修复内容

- 播放块 ID 改为源节点 key 与原始块身份组合，不再包含 `groupPart`。正文、思考等展示分组切换时，共用已有源块游标；展示 owner 仍独立管理注册和清理，不改变折叠、协议队列或工具卡分组。
- 历史识别、动画资格与后台恢复记录同步按源节点身份追踪，避免同一节点换展示分组后被误认为新内容。
- 会话路径的新渐显控制器先接管当前已放行前缀，不把重新挂载时的已有文字再设为透明；控制器挂载后新增的文字仍正常渐显。其他回退路径保留原默认行为。
- 真正的新尝试仍按 generation 重置播放，源块身份没有合并不同重试。

## 回归覆盖

正文、思考两种块分别覆盖“分组展示 → 未分组展示”：切换瞬间源前缀不倒退、不重新渐显，之后继续逐帧增长且新增文字仍有渐显。

接入依赖中真实的官方 `MarkdownText` 和文件打开委托，分别验证正文与思考中的本地文件链接、跨增量冻结边界的引用式链接：已显示文字转换为链接时不重播、不重新渐显；同一节点新增第二个块时仍正常播放；结算后没有留下两份链接。集成环境为 jsdom，并非实机截图或手感验收。

## 行为边界

本修复不枚举或特殊处理 `<…>` 语法，也不修改官方 Markdown 解析器。语法闭合、引用定义到达或最终完整解析时仍可能改变排版、图标和链接外观。官方渲染器如何处理任意原始标签、标签是否进入思考区，取决于真实源数据和官方解析规则；不能用本回归宣称所有未知标签都已验证。

保证进度继承的前提是源节点、块身份与 generation 能保持对应。若上游改写源正文、换了源块身份或发起新的生成，不能假定只是展示重排。

渐显接管是明确的显示规则：渲染器挂载当次已经放行的前缀直接呈现，新控制器只为随后新增字符建立渐显。若首次挂载时已经有一批放行文字，这批也按相同规则接管。

源码体验审阅另确认两项既有边界：原生 seat 随展示分组重挂时，其手动折叠状态并未由本次源游标机制保存；任一块继续播放使整个节点回到 streaming 时，已有本地文件链接可能暂退为文字，最终结算再恢复按钮。它们不是文本再次打字，不包含在本次修复承诺中。真实 WebView 上的反馈一致性仍待验收。
