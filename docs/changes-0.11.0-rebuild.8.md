# 0.11.0-rebuild.8：降低对话期间主线程工作量

本修订在 rebuild.7 上修复持续对话时的重复扫描和广播，并合入键盘缩放及触底手势修复。

## 改动

- 原生卡片的祖先观察器过滤跟随器的 transform、will-change、底部空间等几何样式变动，避免一次公共容器位移触发所有 live 卡片全树扫描。class、hidden、展开状态和其他样式变化仍刷新；包括祖先 class 仅隐藏卡片后代的情况。
- 播放状态表仅在新增状态或活跃成员变化时重新计算淘汰候选；普通文字追加不再因为活跃历史超过 2048 个状态而扫描整个表。保留按最近触碰时间淘汰非活跃状态的行为，不删除活跃状态。
- 已知实时块的普通 text/reasoning delta 继续摄取来源序号和长度，但不广播全会话基线 revision；内容由原有节点订阅更新。首次转为实时、新块、冷加载、历史翻页、重新绑定、来源替换/断流和持久化结算继续通知。
- 稳定播放 Context 的值，减少无关历史组件被唤醒。
- 触底后不抬手反向拖动、轻微向上滚轮在输入任务中立即交还滚动控制，避免下一次内容提交重新钉住底部。
- 合并键盘改变滚动容器高度期间的重复观察器布局处理；非 leader 尽早跳过历史及几何扫描。

## 验证

- 全量 Vitest：23 个文件、400 项测试通过；严格 TypeScript 检查通过。
- 5 张 live 卡片、每张 100 个文本元素：连续公共跟随几何写入不触发 getComputedStyle 或全量 upsert，随后播放正常。
- 3000 个活跃历史源加持续尾部追加：upsert、updateSegments、patch 三种入口均不枚举整个状态表；退休、最近触碰淘汰及重挂载仍通过。
- 40 条历史加一个实时节点：连续原始 delta 包及播放帧不调用历史渲染器、不重新渲染 Flow，来源注册仅涉及实时 owner。
- 触底反向手势覆盖持续输出和完成收尾两个状态；键盘回归模拟同一帧 8 次 resize 通知。

独立 Node CPU 对照（10000 个历史源、420 次尾部更新，去除热身）中，状态表修复使尾部更新中位数由约 2.54ms 降到 0.023ms，P95 由约 5.65ms 降到 0.049ms。这是本机纯 JavaScript 测量，不代表手机浏览器帧率或输入延迟。

尚未取得真实 Android WebView 的性能 trace，也未完成实机动效验收。自定义 CSS 若通过祖先 `[style]` 选择器或容器尺寸查询改变后代可见性，几何过滤可能无法立即感知；常规 class/hidden/display/visibility 变化继续保守刷新。

本候选版沿用 DSH `>=0.2.3-alpha.2 <0.3.0` 兼容范围。生成产物随提交更新；本轮不发布 npm、不替换运行中 profile。安装新版并刷新页面后才会使用新客户端代码。
